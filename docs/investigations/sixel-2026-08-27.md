# Sixel Phase 2 stability investigation

Date: 2026-08-27

Outcome: Defer the independent backend and reuse the Codex TUI implementation during
Phase 3.

## Evidence reviewed

- [OpenAI Codex minimal Sixel encoder](https://github.com/openai/codex/blob/main/codex-rs/tui/src/pets/sixel.rs)
- [OpenAI Codex terminal image integration](https://github.com/openai/codex/blob/main/codex-rs/tui/src/pets/image_protocol.rs)
- [XTerm Sixel control sequence reference](https://invisible-island.net/xterm/ctlseqs/ctlseqs.html#h2-Graphics)

The current Codex implementation has a deterministic in-process RGB332 encoder with
transparent pixels omitted, run length encoding, bounded input indexing, and passive
selection for Windows Terminal and `TERM` markers containing `sixel`, `mlterm`, or
`foot`. It is suitable for Codex's existing ambient image path because that path owns
complete TUI redraw and caching.

## Stability findings

The encoding algorithm is small and does not require a subprocess. It can therefore
be reused safely after adding this project's explicit input and output byte limits.
Its protocol envelope matches XTerm's documented DCS Sixel form and transparent
background parameter.

It does not satisfy the independent transcript backend contract yet:

1. Sixel has no Kitty style image identifier or targeted delete command. Replacing a
   smaller transparent equation can leave pixels from the prior image unless the host
   repaints the complete owned cell rectangle.
2. Cursor and scrolling behavior varies with DEC Sixel display and scrolling modes.
   The independent crate cannot guarantee transcript reflow without cooperation from
   the Ratatui redraw cycle.
3. Worst case encoded size can be much larger than the PNG. A naive 256 plane image
   at the maximum canvas dimensions can produce hundreds of megabytes, so an output
   byte cap and cancellation checks must exist inside the encoder loop.
4. Passive environment markers are not proof of correct placement semantics. Active
   probing is unsafe until Codex's input loop can consume correlated, time bounded
   replies.

## Milestone decision

Do not add `Sixel` to this crate's automatic backend selection during Phase 2. Sixel
terminals continue to receive clean source text. During Phase 3, adapt the existing
Codex encoder inside Codex's full redraw path, add a math-specific byte limit and
cancellation hook, and replay resize, scroll, source toggle, and stale completion
tests before enabling automatic selection.

This decision satisfies the investigation deliverable without advertising a backend
that cannot yet meet the same deletion and reflow guarantees as Kitty and iTerm2.

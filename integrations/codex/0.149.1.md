## Existing assistant transcript flow

The current path is:

1. `tui/src/chatwidget/protocol.rs` receives
   `ServerNotification::AgentMessageDelta` and calls
   `ChatWidget::on_agent_message_delta`.
2. `tui/src/chatwidget/streaming.rs` forwards each nonempty delta into
   `ChatWidget::handle_streaming_delta`.
3. `tui/src/streaming/controller.rs` owns the source collector, stable Markdown
   region, mutable tail, width changes, and final source snapshot.
4. Finalization emits `AppEvent::ConsolidateAgentMessage` from
   `tui/src/chatwidget/streaming.rs`.
5. `tui/src/app/agent_message_consolidation.rs` replaces provisional stream
   cells with one source-backed `AgentMarkdownCell`.
6. `tui/src/history_cell/messages.rs` re-renders that cell from raw Markdown at
   the current width and returns raw source for copy and raw transcript mode.
7. `tui/src/app/history_ui.rs` and `tui/src/app/resize_reflow.rs` write logical
   history lines into physical terminal scrollback and rebuild them on resize.

This is the correct presentation boundary. No change is required in model
context, app-server protocol, stored thread items, or noninteractive output.

## Existing terminal image machinery

Codex already contains the foundation needed for graphical math:

- `tui/src/pets/image_protocol.rs` detects Kitty, WezTerm, Ghostty, iTerm2 3.6
  Kitty local-file transport, Sixel, tmux, and Zellij. It encodes PNG transfer
  and targeted Kitty deletion.
- `tui/src/pets/mod.rs` preserves the cursor, moves to a placement, deletes stale
  images, clears Sixel areas, and flushes terminal output.
- `tui/src/tui.rs` executes image writes through synchronized terminal update
  hooks after Ratatui draws.

Math must reuse this machinery. Copying it into a second TUI subsystem would
create conflicting image identifiers, duplicated detection, and divergent
cleanup behavior.

## Smallest viable integration

### 1. Generalize terminal images without changing pet behavior

Extract the reusable parts of `pets/image_protocol.rs` and `pets/mod.rs` into a
private `tui/src/terminal_image/` module. Keep pet-facing wrappers so the first
upstream patch is a behavior-preserving refactor with existing tests.

The shared module owns backend detection, image identifiers, transfer, placement,
deletion, cursor preservation, and terminal synchronization. Math owns layout
and render lifecycle only.

### 2. Feed deltas to a presentation-only segmenter

Add a math presentation controller beside `StreamController`. Call it from
`ChatWidget::handle_streaming_delta` with the original delta before normal
Markdown rendering. The normal stream still receives the same bytes. Completed
math segments receive stable IDs and enqueue local render work; incomplete
segments remain source text.

Do not replace the accumulated Markdown string. The completed server item remains
authoritative and consolidation still stores the untouched source.

### 3. Correlate asynchronous results through `AppEvent`

Add result events containing thread ID, turn generation, equation ID, and render
result. The app handler discards results for replaced messages, old threads, old
width generations, and cancelled turns before requesting reflow or redraw.

Worker supervision belongs outside `ChatWidget`. The widget must never await a
render or child-process operation on the event loop.

### 4. Extend history cells with optional placement metadata

Add a default-empty placement method to the crate-private `HistoryCell` trait.
`AgentMarkdownCell` can then return source-derived logical lines plus placements
for completed equations while `raw_lines` remains unchanged.

`App::insert_history_cell`, transcript overlay rendering, and resize reflow must
consume lines and placements as one layout result. Merely writing graphics from
`AgentMarkdownCell::display_lines` is unsafe because that method is pure, can be
called during measurement, and does not own terminal synchronization.

Kitty Unicode placeholders should be evaluated in Phase 2 because they naturally
move with text in scrollback. Direct placements remain the proven fallback for
the existing Codex image pipeline.

### 5. Preserve every existing noninteractive path

Raw history, transcript export, redirected output, JSON output, app-server items,
and model context continue using original source. The feature flag is TUI-only
and defaults to text when no safe backend is detected.

## Expected upstream file footprint

| Area | Change |
|---|---|
| `tui/src/terminal_image/` | New shared extraction from pet image code |
| `tui/src/pets/` | Thin adapters to the shared image module |
| `tui/src/math_render/` | New adapter, layout state, and result correlation |
| `tui/src/chatwidget/streaming.rs` | Feed assistant deltas and cancel generations |
| `tui/src/history_cell/mod.rs` | Default-empty placement metadata contract |
| `tui/src/history_cell/messages.rs` | Source-backed math presentation |
| `tui/src/app_event.rs` | Render completion and health events |
| `tui/src/app/history_ui.rs` | Insert lines and image placements atomically |
| `tui/src/app/resize_reflow.rs` | Recompute layout and discard stale placements |
| `tui/src/tui.rs` | Generic synchronized image draw and cleanup hooks |
| TUI configuration types | Feature flag, backend, dollar policy, and limits |

No initial change should be made to `codex-core` or the public app-server API.

## Required Codex tests

- Replay fragmented `AgentMessageDelta` notifications and compare source bytes.
- Snapshot pending, rendered, failed, and raw-source cells.
- Prove the app loop remains responsive while rendering is delayed.
- Reject stale results after resize, thread switch, message replacement, and exit.
- Verify resize reflow deletes old placements before inserting new ones.
- Verify redirected, raw, exported, and app-server output is unchanged.
- Reuse terminal image byte tests for transfer, deletion, and cursor restoration.

## Compatibility conclusion

The integration is feasible and narrower than the original project estimate
because Codex 0.149.1 already contains production-oriented terminal image code.
The main unresolved problem is not image transport; it is attaching asynchronous
image placements to source-backed physical scrollback without weakening resize,
copy, and transcript behavior.
